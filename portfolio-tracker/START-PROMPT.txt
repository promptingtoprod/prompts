## 1. Non-negotiable privacy rules

Hard constraints on the code you write. Put them verbatim in a comment block at the
top of the main file, and don't violate them in any later edit.

1. My financial data — holdings, quantities, book cost, market value, profit,
   account names and numbers, owner names — must NEVER be transmitted off this
   device. It is only ever read from local files and rendered locally.
2. The ONLY outbound network calls are price lookups, and they may send ONLY ticker
   symbols. Confine every network call to two clearly named functions, so there is a
   single auditable boundary. No other function anywhere touches the network.
3. The web server binds to 127.0.0.1 only — never 0.0.0.0, never a LAN IP. No
   authentication is needed precisely because nothing outside this machine can
   connect. Don't add "just expose it for convenience" anywhere.
4. The generated HTML references no external resource — no CDN scripts, no web
   fonts, no remote images, no iframes — and contains zero analytics or telemetry.
   All CSS and JS inlined, so my browser makes no third-party requests either.
5. Include a hard --offline flag (and an env var) that stops ALL network calls and
   falls back to the prices in my file. Say plainly in the README that the flag
   governs this tracker only, not other software on the computer.
6. Write a .gitignore that excludes my data files and caches, and tell me plainly
   not to push this project to GitHub. If I ask you to later, warn me again first.
7. You are an online service: don't read my holdings file unless I point you at it,
   and never copy its numbers into logs, tests, or examples. If I give you sample
   rows instead of the real file, work only from those.

## 3. What to build

One local web dashboard, served on localhost, that opens my browser on launch.
Prioritise by my answers above. The core:

- OVERVIEW — total value, gain/loss against book cost, today's move in dollars and
  percent, and a ranking of which positions drove today's move by DOLLAR impact
  (share count x today's per-share change), not just percent.
- ACCOUNTS — per-account and per-owner, joint accounts counted once.
- POSITIONS — symbol, shares, book cost, price, market value, gain/loss, sortable.
- HISTORY — value over time, saved locally so it accumulates as I run it.
- BENCHMARK — my portfolio against whatever I named.
- LAGGARDS — what I'm currently down on, gathered so I look at it deliberately.
- WATCHLIST + ALERTS — if I asked for them.
- SHUT DOWN WITH THE PAGE — when I close the tab, the server notices and exits, so a
  closed tracker never lingers. A refresh or a second tab must not kill it.

Cache slow-moving data (analyst ratings, earnings dates) locally and refresh at most
once a day, so I'm not hammering the price provider.

LOOK AND FEEL: if TRACKER-DESIGN.md is in this folder, follow it exactly. If not,
ask me; if I don't care, keep it dark, flat and calm — no gradients, no stock
images.

MORE FEATURES: if FEATURE-MENU.md is in this folder, read it AFTER the core works,
show me the list, and ask which I want. Build only what I pick — unless I say "all".


## 4. Tell me the truth about limits

Before I rely on this, print an honest summary — in the chat AND on the dashboard
itself — of what it can do, and then all of this plainly:

- It is NOT investment advice. It reports numbers; nothing it ranks is a suggestion
  to buy or sell.
- It is NOT tax software. No adjusted cost base, no superficial-loss rules, nothing
  I can file. Book values come from my file and may not match what the tax authority
  expects.
- Prices may be delayed, wrong, or missing for a given ticker.
- It cannot place trades and has no connection to my broker. It never modifies my
  file; the only files it writes are its own local ones.
- It does not auto-sync. When I buy or sell, my numbers are stale until I update it.
  Say this loudly — it's the most common way a tracker like this misleads.
- Dividends, splits and corporate actions only show up if my file already has them.
- Multi-currency totals are approximate and depend on when the FX rate was pulled.
- Alerts only fire while the page is open. This is not a notification service.
- The free price provider is an unofficial, unsupported interface with no SLA. When
  it breaks, degrade gracefully and label stale or missing data rather than showing a
  wrong number. Name the provider you chose and tell me to check its terms for my own
  use, since I'm the one making the calls.
- It is NOT a system of record. My broker is. If the two disagree, the broker wins.
